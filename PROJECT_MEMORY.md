## 1. Короткая инструкция для нового аккаунта

1. Клонировать или открыть репозиторий.
2. Прочитать `PROJECT_MEMORY.md`, `README.deploy.md`, `package.json` и файлы
   конкретной игры, над которой предстоит работать.
3. Выполнить `git status --short` и `git log --oneline -20`.
4. Не изменять папки и серверы других игр без прямой просьбы пользователя.
5. После каждой законченной задачи делать отдельный локальный коммит.
6. Перед коммитом запускать как минимум `pnpm typecheck`, а для изменений
   интерфейса, маршрутов, сервера или сборки также `pnpm build`.
7. Не отправлять изменения в GitHub без явной просьбы пользователя. Локальный
   коммит обязателен, push выполняется отдельно.

Готовый промпт для новой сессии:

## 2. Главные договоренности с владельцем проекта

Это обязательные правила, накопленные за все время разработки:

- Каждая игра является самостоятельным модулем со своей логикой, типами,
  серверным хранилищем, Socket.IO-событиями и клиентом.
- При работе над одной игрой нельзя менять игровую логику другой игры без
  прямого запроса. Особенно важно беречь готовые Мафию, Крокодил, Бункер,
  Шпион и Alias.
- Общие компоненты, каталог, оболочку, тему и серверный маршрутизатор менять
  можно только аккуратно, проверяя все доступные игры.
- Любая новая игра создается в отдельной папке `src/games/<game>` и получает
  отдельный сервер `server/<game>Rooms.ts`.
- После каждой завершенной небольшой задачи нужен локальный Git-коммит.
- Не откатывать и не перезаписывать чужие или пользовательские изменения.
- Не упрощать игровую механику до режима наблюдателя. Игроки должны полноценно
  выполнять действия своей роли или этапа.
- Секретная информация всегда фильтруется на сервере для конкретного зрителя.
  Нельзя отправлять все роли, слова, локации или карты клиенту и лишь скрывать
  их CSS.
- При обновлении страницы игрок должен вернуться в ту же сессию, а не создавать
  нового участника.
- Интерфейс должен быть современным, лаконичным и понятным, без нагромождения.
- Светлая и темная темы должны быть одинаково читаемыми.
- На телефоне должен сохраняться весь важный функционал.
- Нельзя оставлять системные `select` и стандартные checkbox, если в соседних
  экранах уже используется фирменный выпадающий список и красный toggle.
- При изменении общей верстки необходимо проверить главную страницу и все игры.

## 3. Видение продукта и дизайн

Project Game — веб-платформа для онлайн-игр с друзьями. Пользователь выбирает
игру, создает открытую или закрытую комнату, приглашает друзей ссылкой или
кодом и играет в реальном времени.

Текущий визуальный язык:

- светлый или глубокий темно-синий фон с атмосферными градиентами;
- кораллово-красный акцент;
- теплый не чисто-белый фон светлой темы;
- крупные выразительные serif-заголовки и спокойный sans-serif для интерфейса;
- единые скругления, границы и внутренние отступы;
- минимальное число одновременно видимых настроек;
- настройки разбиваются на понятные секции и вкладки;
- активные действия заметны, но интерфейс не должен выглядеть перегруженным;
- доступные игры отмечаются зеленой плашкой «Доступно»;
- недоступные игры идут после доступных и отмечаются «Скоро»;
- на карточках игр используются готовые иллюстрации из `public/game-cards`.

Общие элементы находятся в `src/components`. Цвета и базовые стили находятся в
`src/app/globals.css` и конфигурации Tailwind. Перед добавлением нового
визуального паттерна нужно сначала найти аналогичный элемент в существующих
играх.

## 4. Технологии и команды

Стек:

- Next.js 14;
- React 18;
- TypeScript;
- Tailwind CSS;
- Socket.IO 4;
- кастомный Node HTTP-сервер через `tsx`;
- pnpm;
- хранение комнат в памяти процесса.

Основные команды:

```bash
pnpm install
pnpm dev
pnpm typecheck
pnpm build
pnpm start
```

По умолчанию приложение открывается на `http://localhost:3000`. Для запуска на
исторически используемом локальном порту:

```bash
PORT=3002 pnpm dev
```

Если после изменений Next.js появляется ошибка вида
`Cannot find module './987.js'`, это обычно поврежденный кеш `.next`. Нужно
остановить dev-сервер, удалить `.next` и запустить сервер заново:

```bash
rm -rf .next
PORT=3002 pnpm dev
```

## 5. Docker и публикация

Проект содержит `Dockerfile`, `docker-compose.yml`, `.dockerignore` и
`README.deploy.md`.

Запуск:

```bash
docker compose up -d --build
docker compose logs -f
```

Контейнер слушает порт `3000`, наружу он также опубликован как `3000`.
`Dockerfile` специально фиксирует:

- образ `node:20-alpine`;
- `pnpm@9.15.9`;
- multi-stage сборку.

Это исправляет старую проблему, когда Corepack скачивал pnpm 11, который
требовал Node 22 и `node:sqlite`.

Если Docker Hub отвечает `TLS handshake timeout`, это внешняя сетевая проблема,
а не ошибка проекта. Обычно помогает повторная попытка или предварительный
`docker pull node:20-alpine`.

Для Nginx обязательно проксировать WebSocket/Socket.IO с заголовками Upgrade и
Connection. Подробный пример находится в `README.deploy.md`.

Критическое ограничение текущего MVP: комнаты находятся в оперативной памяти
одного Node-процесса. Поэтому:

- перезапуск контейнера удаляет все комнаты;
- нельзя запускать несколько реплик без общего внешнего хранилища и Socket.IO
  adapter;
- для текущей версии нужен один контейнер приложения;
- для полноценного production в будущем нужны Redis или база данных,
  Socket.IO Redis adapter и устойчивые пользовательские сессии.

## 6. Карта архитектуры

### 6.1 Сервер

Главная точка входа: `server/index.ts`.

Она:

- запускает Next.js;
- создает HTTP-сервер;
- подключает Socket.IO по пути `/socket.io`;
- регистрирует обработчики всех игр;
- предоставляет общие REST API.

REST API:

- `POST /api/create-room`
  - тело: `{ gameId, visibility }`;
  - `gameId`: `mafia`, `crocodile`, `bunker`, `spy` или `alias`;
  - `visibility`: `private` или `public`;
  - ответ содержит `code` и `hostKey`.
- `GET /api/room-info?code=XXXXXX`
  - определяет, какой игре принадлежит код;
  - возвращает `code`, `gameId`, `phase`;
  - отвечает `404`, если комнаты нет.
- `GET /api/stats`
  - объединяет реальное число игроков онлайн, активных комнат, комнат за день и
    список открытых комнат всех игр.
- `POST /api/dev/create-mafia-test-room`
- `POST /api/dev/create-bunker-test-room`
- `POST /api/dev/create-spy-test-room`
- `POST /api/dev/create-alias-test-room`

Серверы игр:

- Мафия: `server/rooms.ts`;
- Крокодил: `server/crocodileRooms.ts`;
- Бункер: `server/bunkerRooms.ts`;
- Шпион: `server/spyRooms.ts`;
- Alias: `server/aliasRooms.ts`.

Каждый сервер игры владеет своим `Map` комнат, Socket.IO-событиями, таймерами,
подключениями и формированием публичного состояния.

### 6.2 Клиент комнаты

Маршрут всех комнат: `/room/[code]`.

`src/app/room/[code]/room-router-client.tsx` запрашивает `/api/room-info` и
открывает нужный клиент:

- `room-client.tsx` — Мафия;
- `crocodile-room-client.tsx` — Крокодил;
- `bunker-room-client.tsx` — Бункер;
- `spy-room-client.tsx` — Шпион;
- `alias-room-client.tsx` — Alias.

Если комнаты больше нет, маршрутизатор удаляет устаревшее напоминание о
возврате, чтобы главная страница не предлагала несуществующую комнату.

### 6.3 Сессия игрока

В `localStorage` используются ключи:

- `playerId:<ROOM_CODE>` — идентификатор игрока для переподключения;
- `playerName:<ROOM_CODE>` — имя игрока;
- `hostKey:<ROOM_CODE>` — секрет управления хоста;
- `project-game:last-left-room` — последняя покинутая комната;
- `theme` — выбранная тема.

При перезагрузке клиент сначала пытается подключиться с сохраненным
`playerId`. Сервер должен вернуть существующего игрока и его роль/карты, а не
создавать дубликат. Одинаковые имена в одной комнате запрещены.

### 6.4 Открытые и закрытые комнаты

- Закрытая комната доступна по коду или ссылке.
- Открытая комната отображается на главной странице.
- В списке показываются только актуальные открытые лобби, в которые можно
  войти.
- Панель открытых комнат имеет фиксированную высоту и собственный скролл, а не
  растягивает всю главную страницу.
- Комната, из которой пользователь вышел, может быть закреплена как предложение
  вернуться, пока она действительно существует.
- Пустые или устаревшие комнаты должны удаляться.
- Для Мафии лобби без запущенной игры закрывается через 30 минут.
- Для Шпиона комната без активности и подключенных людей удаляется через
  30 минут.
- При добавлении общей очистки в другие игры нельзя удалить комнату, из которой
  игрок еще может корректно восстановить сессию.

4. Крокодил — 3–20 игроков, 10–30 минут.

группы сохраняется порядок массива `games`: Мафия, Бункер, Шпион, Крокодил,
Alias, затем «Кто я?».

Основные маршруты:

- `/` — главная;
- `/games` — каталог;
- `/games/mafia`;
- `/games/crocodile`;
- `/games/bunker`;
- `/games/spy`;
- `/games/alias`;

показывать поле ввода имени.

## 8. Общие требования к чату

Во всех играх чат должен работать одинаково:

- фиксированная или ограниченная высота;
- новые сообщения создают внутренний скролл, а не растягивают страницу;
- при отправке прокручивается только контейнер чата;
- общий документ не должен прыгать вверх или вниз;
- при открытии вкладки чат показывает последние или первые непрочитанные
  сообщения, а не начало истории;
- во вкладке отображается счетчик непрочитанных;
- перед первым непрочитанным сообщением появляется разделитель
  «Новые сообщения»;
- разделитель не должен исчезать через секунду;
- он исчезает после осознанного просмотра или прокрутки до конца;
- авто-прокрутка к новому сообщению работает, если пользователь уже находился
  около нижней границы;
- поле ввода и кнопка отправки остаются видимыми;
- текст кнопки «Отправить» не сокращается без необходимости.

Для Мафии дополнительно есть приватный чат команды Мафии. Только этот чат должен
быть серым и видимым Мафии/Дону. Обычный чат комнаты следует теме страницы.

## 9. Игра «Мафия»

### 9.1 Изоляция

Логика: `src/games/mafia`.  
Сервер: `server/rooms.ts`.  
Клиент: `src/app/room/[code]/room-client.tsx`.  
Dev-режим: `/dev/mafia-test`.

Не изменять эти файлы при работе над другой игрой без прямого запроса.

### 9.2 Роли

- `CIVILIAN` — мирный житель;
- `MAFIA` — мафия;
- `DON` — Дон мафии;
- `MISTRESS` — любовница;
- `DETECTIVE` — комиссар/шериф;
- `DOCTOR` — доктор.

Дон является отдельным дополнительным участником команды Мафии. Настройка
«одна мафия + Дон» означает одного обычного мафиози и одного Дона, а не замену
мафиози Доном.

Любовница не считается Мафией, не входит в условие победы Мафии и не знает
мафиози. Мафия также не получает личность любовницы.

### 9.3 Фазы

```text
LOBBY
ROLE_REVEAL
NIGHT_MAFIA
NIGHT_MISTRESS
NIGHT_DON
NIGHT_DETECTIVE
NIGHT_DOCTOR
DAY_DISCUSSION
DAY_VOTING
DAY_REVOTE
DAY_TIE_CHALLENGE
GAME_OVER
```

Ночная фаза отсутствует полностью, если соответствующая роль не была включена
до старта игры. Если роль была в игре, но затем выбыла, ее скрытая фаза все
равно наступает и автоматически длится случайные 10–20 секунд. Таймер этой
пустой фазы не показывается, чтобы остальные игроки не поняли, что активная
роль погибла.

### 9.4 Основная механика

- Роли выдаются только подключенным игрокам, не ведущим-наблюдателям.
- После раздачи каждый игрок подтверждает, что ознакомился с ролью.
- Хост может выбрать участие как игрок или роль ведущего.
- Игра может идти без ведущего, потому что все действия выполняются в UI.
- Играющий хост не видит чужие роли.
- У активной роли можно выбрать только одного игрока за фазу и изменить выбор
  до подтверждения.
- После действия кнопка продолжения появляется у действующего игрока, а не у
  хоста.
- В ручном режиме фаза продолжается после нужных подтверждений.
- В режиме таймера отдельное время настраивается для Мафии, Дона, комиссара,
  доктора, обсуждения и голосования.
- Во время обсуждения все живые игроки нажимают «Перейти к голосованию».
- Во время голосования должны проголосовать все живые игроки.
- Игрок видит себя в списке и может голосовать за себя.
- Выбор можно изменить до подтверждения.

Мафия:

- несколько мафиози выбирают жертву;
- они видят выбор друг друга прямо на карточках целей;
- выбор можно менять;
- при одинаковом выборе можно завершить фазу;
- при разногласии выбор не блокируется;
- Дон участвует в убийстве и отдельно ищет комиссара;
- настройка `donVoteMode` определяет решающий голос Дона или равный голос;
- при решающем Доне его выбор может автоматически стать итоговым после
  30 секунд, если команда не пришла к согласию.

Комиссар:

- проверяет ровно одного игрока за ночь;
- видит результат только в текущей фазе;
- прошлый результат не должен постоянно раскрывать проверенного игрока.

Доктор:

- выбирает одного игрока и отменяет убийство этой ночью;
- по умолчанию не может лечить одного и того же игрока две ночи подряд;
- настройка разрешает повторное лечение без ограничения.

Любовница:

- ходит в отдельную фазу;
- может изменить цель до подтверждения.

### 9.5 Голосование и ничья

Настройки:

- публичное или анонимное голосование;
- по умолчанию публичное;
- при публичном видны выборы игроков как у команды Мафии;
- при анонимном все равно виден счетчик проголосовавших и кнопка подтверждения.

Режимы равенства:

- переголосование между лидерами;
- никто не выбывает;
- испытание на вылет.

При повторном равенстве обычного переголосования могут выбыть все оставшиеся
лидеры, если это выбранное правило.

Испытание длится 30 секунд. Претенденты сначала подтверждают готовность, затем
решают последовательность быстрых заданий. Типы:

- простые арифметические примеры с вариантами ответа;
- «чего не хватает»: показанная строка содержит слова/символы, а правильный
  ответ — элемент, которого в строке нет.

После правильного ответа сразу выдается следующее задание. Побеждает игрок с
наибольшим числом правильных ответов. Счет обоих претендентов виден им и
наблюдателям. База заданий большая, чтобы повторы были редкими.

- Карточка бункера использует атмосферное изображение пещеры и отдельные
  красные неоновые иконки мест, комнат и проблем.
- В светлой теме текст на темной иллюстрации должен оставаться светлым и
  контрастным.
- Изображение, рамка и текст не должны обрезаться или расходиться.

### 11.5 Классический и быстрый режим

- Классический режим использует полный набор выбранных характеристик.
- Быстрый режим ограничивает игровой набор примерно шестью доступными
  характеристиками.
- Ограничение быстрого режима должно соблюдаться:
  - в собственной колоде;
  - в выборе карты для раскрытия;
  - при применении спецкарты «Открыть еще карту»;
  - при просмотре других игроков.
- Если все доступные карты раскрыты, а исключения еще требуются, игра должна
  продолжать цикл обсуждения и голосования без требования открыть
  несуществующую карту.

### 11.6 Раскрытие и подтверждение

- Профессия может быть раскрыта при старте.
- В каждом раунде игрок раскрывает не более одной обычной характеристики.
- При свободном порядке игрок выбирает любую доступную характеристику.
- После выбора каждый активный игрок отдельно подтверждает свой выбор.
- Нельзя перейти к обсуждению или голосованию, пока все активные подключенные
  игроки не выбрали и не подтвердили характеристику.
- При включенном таймере остаток времени виден.
- Если таймер выбора истек, сервер выбирает случайную допустимую
  характеристику за не успевшего игрока.

### 11.7 Голосование

- Каждый игрок выбирает кандидата и отдельно подтверждает голос.
- До подтверждения голос можно изменить.
- Исключение происходит автоматически только после подтверждения всех
  обязательных голосов или корректного истечения таймера.
- При истечении таймера голос непроголосовавшего используется против него
  самого.
- Хост не должен вручную подсчитывать неполные голоса.
- Поддерживаются открытое и анонимное голосование.
- Ничья: переголосование, отсутствие исключения или случайный выбор согласно
  настройке.
- После результата есть единая заметная кнопка продолжения.
- Выбывший игрок получает заметную постоянную плашку и закрываемую модалку.

### 11.8 Спецкарты

Текущие рабочие типы:

```text
reveal_extra
hide_card
force_reveal
swap_card
protect_vote
protect_player
reroll_card
double_vote
reset_votes
```

Не добавлять:

- «Отмена спецкарты» — она была удалена как практически неприменимая;
- «Вернуть спецкарту» — у игрока одна спецкарта за игру, поэтому карта часто
  оказывалась бесполезной до использования другой карты.

Любая спецкарта должна:

- иметь реальный серверный обработчик;
- быть применима в понятной фазе;
- корректно проверять цель;
- не раскрывать секретные карты посторонним;
- не блокировать переход фазы;
- иметь понятное описание;
- открываться в увеличенной модалке по нажатию;
- отображать причину недоступности;
- использоваться только один раз, если явно не задано иное.

## 14. Тема и адаптивность

Требования:

- интерфейс меняет цвет без исчезновения содержимого;
- анимация распространяется по диагонали от верхнего левого угла к нижнему

  стилизованных иллюстраций Бункера;

- кнопка прокрутки наверх на телефоне одна, красная и использует плавный
  `scroll-behavior`, без второй системной стрелки.

Мобильные требования:

- доступны «Войти по коду» и создание комнаты;
- элементы шапки не накладываются на логотип;
- знак `+` и текст кнопки создания находятся на одной строке;
- модалки и custom-select помещаются в viewport;
- игровые кнопки и счетчики не создают горизонтальный скролл;
- длинные списки игроков, комнат и сообщений прокручиваются внутри своих
  панелей.

- проверить создание открытой и закрытой комнаты;
- проверить вход, обновление страницы и возврат тем же игроком;
- проверить хоста и обычного игрока в разных вкладках;
- проверить чат на большом количестве сообщений;
- проверить недоступность секретов чужому клиенту;
- проверить таймер и ручной режим;
- проверить ничью и неполные голоса;
- проверить offline/disconnect/reconnect;
- проверить завершение игры.

В проекте пока нет полноценного автоматического test runner. Во время
разработки использовались целевые `tsx`-скрипты и тестовые Socket.IO-клиенты.
Исторически успешно проверялись:

- полная production-сборка;
- TypeScript;
- персональная секретность Шпиона;
- три одновременных клиента Шпиона и reconnect;
- ничьи и таймеры Шпиона;
- фазы и роли Мафии;
- переголосование Мафии;
- Бункер с готовностью, раскрытием, голосованием и быстрым режимом;
- уникальность и размер словаря Крокодила;
- движок, realtime-приватность, защита от двойного клика и 400 слов Alias.

Для сложной логики лучше добавлять постоянные unit/integration tests, а не
оставлять только одноразовую команду.

## 17. Git-процесс

Текущие данные на момент создания:

```text
branch: main
remote: origin -> https://github.com/Iutin12/Project-Game.git
commit: 4bf7e43
commits in repository: 132
```

Обычный цикл:

```bash
git status --short
git diff
pnpm typecheck
pnpm build
git add <конкретные файлы>
git commit -m "Краткое описание завершенной задачи"
```

Пользователь просил делать локальные коммиты даже после небольших задач. Если в
одном запросе несколько независимых пунктов, предпочтительно сделать несколько
логичных коммитов, а не один огромный. Push:

```bash
git push origin main
```

выполняется только после отдельной просьбы.

## 18. Известные ограничения и технический долг

- Все комнаты хранятся в памяти процесса.
- Нет аккаунтов, базы данных и долговременной статистики.
- Нет горизонтального масштабирования.
- `README.md` устарел: он все еще описывает Мафию как единственную готовую игру.
  Более точная информация находится в этом файле и коде.
- Клиенты комнат крупные, особенно `room-client.tsx` Мафии и
  `bunker-room-client.tsx`; будущий безопасный рефакторинг должен разбивать их
  на компоненты без изменения логики.
- Нет общей библиотеки типизированных Socket.IO-событий.
- Общие паттерны чата, custom-select, готовности и настроек частично
  продублированы между играми. Их можно вынести в общие компоненты только после
  сравнительного тестирования всех игр.
- Нет стабильного автоматического e2e-набора.
- Статистика «комнат создано сегодня» и online реальна только в пределах
  текущего процесса и сбрасывается после рестарта.
- Browser automation в некоторых средах Codex падал с
  `Cannot redefine property: process`; в таком случае использовать ручную
  проверку, Socket.IO-скрипты и build, а не считать интерфейс проверенным без
  просмотра.

## 19. Как добавлять следующую игру

1. Прочитать ее ТЗ.
2. Создать `src/games/<id>` с `types.ts`, чистой логикой, настройками и
   персональной фильтрацией состояния.
3. Создать `server/<id>Rooms.ts`.
4. Создать отдельный клиент комнаты.
5. Подключить игру в `server/index.ts` и `room-router-client.tsx`.
6. Добавить карточку в `src/games/config.ts`.
7. Добавить страницу игры и подробные правила.
8. Добавить dev/test-страницу.
9. Реализовать открытые и закрытые комнаты, статистику, сессии, reconnect,
   чат, unread, тему и mobile.
10. Проверить, что Мафия, Крокодил, Бункер, Шпион и Alias не изменили поведение.
11. Делать небольшие последовательные коммиты по слоям: engine, server,
    interface, registration, dev tools, hardening.

## 20. Приоритет истины при расхождении

Если новый запрос противоречит старому поведению, приоритет такой:

1. последняя явная просьба пользователя;
2. текущий работающий код и тесты;
3. этот файл;
4. исходное ТЗ;
5. старые сообщения и ранние макеты.

Если изменение имеет скрытые последствия для другой игры, нужно остановиться,
кратко объяснить риск и согласовать только действительно неоднозначное решение.
Во всех остальных случаях следует самостоятельно выполнить задачу до конца,
проверить и закоммитить.
